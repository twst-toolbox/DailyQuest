# 最终形态设计：多游戏队列 + 定时任务 + 失败报告

日期：2026-10-19
目标设备：红米 Note 14 Pro+（MIUI）
对齐参考：MAA 手机版

---

## 用户使用流程（最终版）

### 日常手动执行
1. 打开 DailyQuest，看到游戏列表（扭曲仙境日服/美服、FGO、明日方舟...）
2. 勾选要执行的任务（比如"扭曲仙境-签到+上课"、"FGO-签到"）
3. 点"开始任务"按钮
4. 应用提示"即将开始，请保持屏幕常亮"，自动：
   - 启动前台服务（通知栏显示"执行中：扭曲仙境 日服"）
   - 请求 MediaProjection 授权（首次授权一次，之后复用）
   - 调用 `keepScreenOn()` 保持屏幕常亮
5. 自动打开扭曲仙境，执行签到、上课清体力、退出
6. 自动打开 FGO，执行签到，退出
7. 全部完成后：
   - 恢复屏幕常亮设置
   - 显示"执行报告"（成功/失败列表）
   - 你手动息屏或继续用

### 定时自动执行
1. 设置 → 定时任务 → 添加（每天 08:00，勾选要执行的游戏）
2. MIUI 自启动管理 → 允许 DailyQuest 自启动
3. 电池优化 → 加入白名单
4. 每天 08:00：
   - AlarmManager 唤醒 DailyQuest 前台服务
   - 如果屏幕是黑的 → 发送高优先级通知（触发 MIUI 亮屏）
   - 如果屏幕亮着 → 直接开始执行（流程同上）
   - 执行完发通知"任务完成：扭曲仙境 成功，FGO 失败（网络错误）"

## 关键技术点

### 1. MediaProjection 授权策略（MIUI 实测可行）
- **首次**：手动点"授权屏幕录制"，勾选"不再询问"（MIUI 支持）
- **之后**：前台服务持有 MediaProjection 会话，只要服务不被杀，授权一直有效
- **定时任务**：直接复用已有会话，不用重复弹窗
- **异常处理**：如果会话失效（比如重启手机），定时任务发通知"请手动打开 DailyQuest 重新授权"

### 2. 息屏处理（MIUI 限制下的最佳方案）
- **无法自动解锁**：MIUI 不允许应用自动解锁屏幕（即使有自启动权限）
- **可行方案**：
  a) 任务执行期间保持屏幕常亮（`WakeLock` + `FLAG_KEEP_SCREEN_ON`）
  b) 定时任务触发时，如果屏幕黑 → 发高优先级通知（MIUI 会亮屏显示通知）
  c) 你点通知 → 自动跳转到 DailyQuest 并开始执行
- **推荐设置**：MIUI 设置 → 息屏与锁屏 → 双击亮屏（开启），这样通知来了双击就能亮

### 3. 失败重试与报告（核心需求）
每个游戏执行时记录状态：
```kotlin
data class TaskResult(
    val gameId: String,
    val taskName: String,
    val status: Status,  // SUCCESS / FAILED / SKIPPED
    val reason: String?,  // 失败原因（如"网络连接超时"、"找不到按钮"）
    val retryCount: Int,
    val screenshot: String?  // 失败时的截图路径
)
```

**失败处理逻辑**：
1. 单个任务失败（比如网络错误）：
   - 自动重试 3 次（每次间隔 10 秒）
   - 仍失败 → 记录到报告，**跳过这个游戏，继续下一个**
2. 全部完成后：
   - 显示报告页面：成功列表（绿色）+ 失败列表（红色，附原因和截图）
   - 失败的游戏可以单独重跑

**典型失败场景**：
- 网络连不上（通信エラー弹窗）→ 重试 3 次后跳过
- 找不到按钮（UI 变化）→ 记录截图，跳过
- 游戏闪退 → 检测到包名不在前台，重新启动游戏重试 1 次

### 4. 多游戏队列（串行执行）
```kotlin

// 串行执行，一个完成再下一个
for (task in queue) {
    val result = executeGame(task)
    report.add(result)

        // 继续下一个，不中断队列
    }
```

## MIUI 特别注意事项

1. **自启动管理**：设置 → 应用设置 → 授权管理 → 自启动管理 → DailyQuest（开启）
2. **省电策略**：设置 → 省电与电池 → 应用智能省电 → DailyQuest → 无限制
3. **锁屏清理**：设置 → 省电与电池 → 锁屏后清理内存 → 关闭（或把 DailyQuest 加入白名单）
4. **通知权限**：允许 DailyQuest 发送通知（用于失败提醒和定时任务触发亮屏）
5. **悬浮窗权限**：必须开启（用于显示执行状态和控制面板）

## 与 MAA 手机版的对比

| 功能 | MAA 手机版 | DailyQuest | 备注 |
|---|---|---|---|
| 定时任务 | 需要 Shizuku | 不需要（AlarmManager） | 我们更简单 |
| 熄屏拉起 | Shizuku 实现 | 通知亮屏 + 手动点 | 我们多一步，但免 root |
| 多游戏队列 | 不支持（只支持方舟） | 支持（无限扩展） | 我们更灵活 |
| 失败报告 | 有 | 有（更详细，含截图） | 我们更友好 |
| 自定义脚本 | 不支持 | 支持（录制模式） | 我们更自由 |
| 分辨率适配 | 固定分辨率 | 动态缩放 | 我们更通用 |
